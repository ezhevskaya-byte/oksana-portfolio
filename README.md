## Техническая основа

Статический сайт на HTML, CSS и JavaScript без сборки. Smart Brief — интерфейс диалога с Марком; его серверная часть находится в отдельном Cloudflare Worker.

### Структура

- `index.html`, `cases/` — главная страница и страницы кейсов.
- `css/`, `js/`, `images/` — стили, клиентская логика и изображения.
- `smart-brief/index.html`, `css/smart-brief.css`, `js/smart-brief.js` — Smart Brief frontend.
- `smart-brief/docs/` — проектные материалы Smart Brief.
- `smart-brief-worker/src/` — API, диалоговая логика, провайдеры AI, STT и ограничения запросов.
- `smart-brief-worker/scripts/` — локальные тесты и отдельные live-проверки.
- `robots.txt`, `sitemap.xml` — правила индексации и карта сайта.
- `server.js` — локальный HTTP-сервер; `AGENTS.md` — правила работы агентов.

### Локальная разработка

Нужны Node.js и npm. Для статического сайта установка зависимостей не требуется: запустите `node server.js` из корня. Сервер слушает только `127.0.0.1:5173`. Если порт занят, в PowerShell можно выбрать другой:

```powershell
$env:PORT = '5174'
node server.js
```

Статический сервер не запускает Worker. Для отдельной разработки Worker выполните в `smart-brief-worker` команды `npm ci` и `npm run dev`. Требуемые переменные перечислены в `.dev.vars.example`; реальные значения храните только в локальном игнорируемом `.dev.vars`. Локальный запуск frontend сам по себе не гарантирует, что его запросы направлены на локальный Worker: проверяйте адрес API до отправки запросов.

### Проверки

Из каталога `smart-brief-worker`:

```powershell
npm run check
npm test
```

`check` проверяет синтаксис серверного кода. `test` запускает локальные проверки диалога, провайдеров, STT, ограничений, HTTP с заглушками и жизненного цикла frontend. Live-скрипты и команды deploy не входят в обычную локальную проверку.

Для сайта проверьте главную страницу, `/smart-brief/`, страницы кейсов, `/robots.txt` и `/sitemap.xml` через локальный сервер. Перед завершением работы изучите `git status` и `git diff --check`.

Текстовые файлы нормализуются в LF согласно `.gitattributes`; бинарные файлы определяются автоматически. Публикация сайта и Worker выполняется только по отдельному разрешению.
